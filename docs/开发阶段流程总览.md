二、建议拆成这 10 个节点
节点 0：仓库和资料初始化

只做准备，不写业务功能。

步骤：

创建项目目录。
放入最新版 agent.md、PRD.md 和两张参考图。

建立 .gitignore。
确定目录结构。
检查 Windows、Node、npm 环境。
建立初始提交。

完成标志：

资料齐全
仓库干净
目录明确
没有业务代码
节点 1：前后端基础工程

只搭项目骨架。

步骤：

创建 Vue 3 + TypeScript + Vite。
创建 Fastify + TypeScript。
建立前后端启动命令。
建立统一配置。
建立日志。
建立错误处理。
创建 /api/v1/health。
建立基础测试。
前端能够请求后端健康接口。

完成标志：

前端可打开
后端可启动
健康接口正常
类型检查通过

五、节点 6：按顺序合并模块

建议合并顺序：

1. 菜谱、食材与厨房
2. 店铺与觅食
3. 计划与购物清单
4. 日记、食用者与统计

步骤：

每次只合并一个分支。
合并后运行全量类型检查。
运行数据库迁移。
运行 API 测试。
运行 UI 回归。
修复后再合并下一个。
删除正式代码中的 Mock。
统一路由、样式和公共组件。

不要四个分支一次性全部合并。

六、节点 7：推荐系统和完整业务闭环

模块数据齐全后，再完成真实推荐和闭环。

步骤：

接入菜谱候选。
接入店铺候选。
接入库存匹配。
接入厨房工具过滤。
接入食用者忌口和过敏。
接入重复周期。
完成普通、随机和尝鲜模式。
完成搭配一顿饭。
推荐结果加入计划。
缺少食材加入购物清单。
完成计划生成记录草稿。
生成库存扣减预览。
确认扣减并写库存日志。
更新统计。

完整闭环应为：

新增菜谱
→ 添加库存
→ 推荐
→ 加入计划
→ 完成计划
→ 生成日记
→ 扣减库存
→ 生成购物清单
→ 更新统计

这是 PRD 的核心验收链路。

生成二维码。
增加防火墙说明。
自动备份。
手动备份。
恢复校验。
恢复失败回滚。
验证电脑重启后的完整流程。

PRD 要求最终尽量做到解压后双击启动，不要求用户安装 SQLite、Prisma、Docker 或其他数据库。
