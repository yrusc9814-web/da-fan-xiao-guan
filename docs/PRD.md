# 2. 产品定义

## 2.1 产品定位

搭饭小馆是一套本地饮食决策、菜谱管理、库存管理、用餐计划和饮食记录工具。

核心解决的问题：

1. 今天不知道吃什么。
2. 想根据现有食材搭配一顿饭。
3. 想优先消耗即将过期或积压食材。
4. 想记录菜谱、店铺和常吃内容。
5. 想减少短期内重复用餐。
6. 想管理早餐、午餐、晚餐等每日计划。
7. 想记录吃过什么并查看基础统计。
8. 想根据缺少食材快速生成购物清单。
9. 想在电脑和手机上查看同一份本地数据。
10. 不希望部署复杂云服务或额外数据库。

## 2.2 产品目标

```text
录入菜谱、店铺、食材和工具
        ↓
本地规则推荐
        ↓
形成一顿饭或单项推荐
        ↓
加入每日计划
        ↓
完成用餐
        ↓
生成饮食记录草稿
        ↓
确认库存扣减
        ↓
缺少食材进入购物清单
        ↓
更新日历和统计
```

## 2.3 产品原则

- 本地优先。
- 数据真实持久化。
- 手机优先但不牺牲桌面效率。
- 推荐过程可解释。
- 关键操作可撤销或恢复。
- AI 为可选增强，不是核心依赖。
- 不引入会员、广告、订阅和商业推广。
- 不输出专业医疗或营养诊断。
- 不依赖 Docker、PostgreSQL 或云数据库。
- 页面关闭和电脑重启后数据必须保留。

## 2.4 第一版非目标

第一版不实现：

- 多账号和复杂权限。
- 公网访问。
- 云端同步。
- 电商平台购买接口。
- 外卖平台下单接口。
- 地图导航和实时距离。
- 医疗级营养分析。
- 条码扫码。
- 语音助手。
- 原生 iOS 或 Android App。

# 3. 用户、访问与首次启动

## 3.1 使用角色

### 管理者

默认唯一管理角色，可以：

- 管理菜谱、食材、厨房工具和店铺。
- 管理计划、记录、食用者和购物清单。
- 查看统计。
- 配置访问 PIN。
- 备份和恢复数据。
- 修改系统设置。

### 食用者

食用者不是登录账号，只作为计划、记录和推荐条件中的对象。

示例：

- 自己
- 伴侣
- 家人
- 朋友

## 3.2 访问方式

默认采用简单 PIN：

- PIN 可以关闭。
- PIN 只保存安全哈希。
- 登录状态默认保留 30 天。
- 恢复备份、清空数据等高风险操作需要再次验证。
- 不建设注册、邮箱和短信验证。

## 3.3 首次启动向导 `ONBOARD-*`

### ONBOARD-001 基础资料

首次启动时引导设置：

- 用户昵称
- 用户头像，可跳过
- 项目副标题，可使用默认值
- 默认食用者

### ONBOARD-002 安全设置

- 是否开启访问 PIN
- 设置 PIN
- 局域网访问说明

### ONBOARD-003 使用偏好

- 默认不重复周期
- 默认餐次数量
- 是否完成计划后生成日记草稿
- 是否显示库存扣减预览
- 是否开启每日自动备份

### ONBOARD-004 完成状态

向导完成后写入设置表，后续不重复显示，可在设置中重新打开。

# 5. 首页需求

# 5.1 桌面端首页 `HOME-D-*`

桌面端采用：

```text
左侧固定导航 + 右侧主内容区
```

模块顺序必须固定。

## HOME-D-001 顶部栏

包含：

- 全局搜索框
- 通知入口
- 可选日历快捷入口
- 用户头像
- 用户昵称
- 用户菜单

搜索范围：

- 菜谱名称、食材和标签
- 店铺名称、菜系和菜品
- 饮食记录名称和备注
- 购物清单内容

## HOME-D-002 问候横幅

包含：

- 动态问候语
- 用户昵称
- 简短副文案
- 小羊主插画
- 少量花盆、云朵、爱心或清单装饰

问候语根据本地时间变化：

- 05:00–11:59：早上好
- 12:00–17:59：下午好
- 18:00–04:59：晚上好

## HOME-D-003 四个核心快捷入口

固定为一行四列：

1. 随机决定
2. 搭配一顿饭
3. 库存消耗
4. 库存推荐

每张卡包含：

- 标题
- 两行以内说明
- 本地插画
- 主操作按钮

## HOME-D-004 今日推荐菜谱

横向占满主内容区。

要求：

- 默认展示 5–6 张卡片。
- 卡片显示图片、名称、标签、制作时长和评分。
- 提供“查看更多”。
- 内容超出时支持横向滚动或分页。
- 不再与库存概览并排。
- 不允许缩回半宽区域。

## HOME-D-005 三列信息卡

顺序固定：

```text
左：今日饮食记录
中：本周统计
右：库存概览
```

今日饮食记录只允许出现一次。

库存概览包含：

- 食材总数
- 即将过期数量
- 库存不足数量
- 即将过期食材列表
- 查看全部

## HOME-D-006 饮食日历

横向占满主内容区。

包含：

- 当前一周或日期范围
- 上一周期
- 下一周期
- 今天高亮
- 计划、记录、推荐或收藏状态标记

## HOME-D-007 侧栏小贴士

侧栏底部显示“搭饭小贴士”：

- 小羊插画
- 今日库存提醒
- 今日计划提醒
- 本地饮食提示

禁止出现会员、升级、订阅、广告和推广。

可多选：

- 早餐

- 晚餐
- 下午茶
- 汤品

## RECO-003 获取方式

可多选：

- 自己做
- 到店
- 外卖

## RECO-004 标签

默认包括：

- 辣
- 清淡
- 减脂
- 快手菜
- 一人食
- 下饭
- 素食
- 肉类
- 海鲜
- 主食

支持用户自定义。

## RECO-005 重复周期

支持：

- 不限
- 3 天
- 5 天
- 1 周
- 1 个月
- 3 个月

## RECO-006 想吃与不想吃

支持逗号分隔输入，匹配：

- 菜名
- 食材
- 标签
- 店铺类型
- 菜系

## RECO-007 随机程度

- 普通：加权随机
- 完全随机：硬条件候选中均匀随机
- 尝鲜：优先从未吃过、低频或从未推荐内容

## RECO-008 硬条件

不满足时必须排除：

- 餐次
- 获取方式
- 不想吃关键词
- 重复周期
- 食用者忌口
- 食用者过敏
- 必须消耗指定食材
- 必须具备必要厨房工具
- 仅使用已有食材

## RECO-009 软权重

参与排序：

- 想吃关键词
- 收藏状态
- 个人评分
- 库存匹配度
- 即将过期食材
- 最近未吃
- 最近未推荐
- 新尝试
- 历史接受率

## RECO-010 推荐结果

显示：

- 图片
- 名称
- 类型
- 推荐原因
- 命中条件
- 可消耗库存
- 最近食用时间
- 评分
- 标签
- 缺少食材

操作：

- 加入计划
- 换一个
- 收藏
- 查看详情
- 标记不想吃
- 将缺少食材加入购物清单

## RECO-011 推荐历史

每次保存：

- 推荐类型
- 筛选条件
- 候选数量
- 推荐结果
- 是否接受
- 是否加入计划
- 推荐时间

# 8.2 单位与换算 `UNIT-*`

## UNIT-001 支持单位

- 升

- 个
- 盒

- 份

## UNIT-002 自动换算

允许自动换算：

```text
1 千克 = 1000 克
1 升 = 1000 毫升
```

## UNIT-003 不可换算单位

“个、盒、袋”等计数单位不能与重量单位自动换算。

需要人工确认时，系统必须提示。

## UNIT-004 自动扣减限制

出现以下情况时不得自动扣减：

- 菜谱食材没有数量
- 单位不可换算
- 食材未关联库存条目
- 库存数量不足
- 多个库存条目无法自动选择

# 16. 数据并发与多设备访问

# 16.1 使用场景

电脑和手机可能同时打开并编辑同一条数据。

# 16.2 乐观锁 `CONFLICT-*`

以下表增加版本号或使用 `updated_at` 条件更新：

- 菜谱
- 食材
- 店铺
- 计划
- 饮食记录
- 食用者
- 购物清单
- 设置

更新请求必须携带当前版本。

版本不一致时：

- 返回 409。
- 提示“数据已在其他设备修改”。
- 提供刷新后重试。
- 不允许后提交的数据静默覆盖。

# 16.3 实时性

第一版不要求 WebSocket 实时同步。

页面进入、保存成功和手动刷新时重新拉取数据。

# 17. 关键交互规范

## 17.1 新增和编辑

移动端：

- 底部抽屉或全屏表单
- 底部固定保存按钮
- 避开安全区

桌面端：

- 简单表单使用居中弹窗
- 长表单使用右侧抽屉
- 最大宽度合理限制

## 17.2 删除

- 删除前确认
- 历史关联数据优先软删除
- 最近 30 天内可恢复
- 高风险清空操作再次验证 PIN

## 17.3 加载与错误

所有页面必须有：

- 加载状态
- 空状态
- 错误状态
- 保存状态
- 删除确认
- 操作成功反馈

请求失败必须保留表单内容。

## 17.4 撤销

删除、清空已完成购物项等操作应提供短时间撤销。

# 27. 验收标准

## 27.1 品牌与首页

1. 项目名称为“搭饭小馆”。
2. 副标题为“让每一餐都更美好”。
3. 双端小羊角色风格统一。
4. 桌面推荐菜谱全宽。
5. 桌面第三行为记录、统计、库存三列。
6. 今日饮食记录只出现一次。
7. 桌面日历全宽。
8. 移动快捷入口为两列。
9. 移动推荐菜谱可横向滑动。
10. 移动底栏为首页、厨师、觅食、日记。

## 27.2 功能

1. 新增菜谱后刷新和重启仍存在。
2. 菜谱食材可参与库存匹配。
3. 一顿计划可以包含多道菜。
4. 一条饮食记录可以包含多项。
5. 推荐条件真实生效。
6. 重复周期真实影响结果。
7. 推荐可加入计划。
8. 计划完成生成记录草稿。
9. 库存扣减先显示预览。
10. 不可换算单位要求人工确认。
11. 缺少食材可生成购物清单。
12. 购物清单可勾选和清理。
13. 统计来自真实数据库。
14. 食用者忌口和过敏影响推荐。
15. 电脑和手机访问同一数据。

## 27.3 数据与并发

1. 关键操作使用事务。
2. 数据库变更使用 Prisma Migration。
3. 图片保存在本地目录。
4. 同一记录被其他设备修改时返回冲突。
5. 不允许静默覆盖其他设备的新数据。
6. 软删除不破坏历史统计。

## 27.4 部署与恢复

1. 双击启动脚本可运行。
2. 停止脚本不误杀其他进程。
3. 设置页显示手机访问地址和二维码。
4. 自动备份可生成。
5. 手动备份可恢复。
6. 恢复失败可回滚。
7. Windows 重启后数据仍完整。
